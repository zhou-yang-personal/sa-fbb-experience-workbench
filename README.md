# SA FBB Experience Workbench

SA FBB Experience Workbench 是一个本地 EXE 数据分析工作台，用于处理 SA 单板输出的家宽 TCP / Game 应用体验 CSV 数据，完成大文件原样入库、MySQL 库内清洗、聚合分析、Cable/FTTH 体验对比和 Cable-to-Fiber 迁转升套机会识别。

当前版本：

```text
1.0.69
```

## 1. 核心目标

1. 支持千万级 CSV 文件不经应用内内存清洗，优先原样导入 MySQL RAW 表。
2. 基于 MySQL 完成 RAW → CLEAN/DWD → DWS/ADS 分层清洗和聚合。
3. 支撑总览、应用分类、体验质量、Cable vs FTTH、迁转升套机会等看板。
4. 输出可复核、可重跑、可导出的用户级机会名单。
5. 通过 CRM、FTTH 覆盖、可触达状态完成最终营销名单融合。

## 2. 架构原则

核心链路：

```text
CSV 文件选择
→ 文件元信息登记
→ MySQL RAW 表原样高速导入
→ MySQL 库内清洗 / 标准化 / 衍生字段
→ CLEAN / DWD 明细层
→ CLEAN 与 RAW 入库完整性质量验证
→ DWS / ADS 聚合与看板结果层
→ CRM / 覆盖 / 触达融合
→ 用户名单 / 汇总结果导出
```

详细设计见：`docs/design/current-core-design.md`。

产品功能树见：`docs/design/product-function-tree-v0.2.md`。

## 3. Phase 1-7 完整应用基线

1. Phase 1：本地工程骨架、版本文件、MySQL 连接、数据库初始化。
2. Phase 2：大 CSV 导入入口、批次管理、RAW 入库主路径。
3. Phase 3：RAW 质量门禁、RAW → CLEAN、完整 DWS 聚合。
4. Phase 4：Overview、应用分类、体验质量、Cable vs FTTH 看板 ADS。
5. Phase 5：Lead scoring、瓶颈归因、迁转升套分层。
6. Phase 6：CRM、FTTH 覆盖、可触达状态融合，生成最终营销动作。
7. Phase 7：导出、handoff、changelog、交付检查入口。

## 4.2 1.0.67 公共聚合核心

- 以“用户 × App × 日期 × 小时”为唯一公共体验核心；DWD 只在按小时分片构建核心时读取。
- 核心保留每个指标的 `SUM/COUNT` 可累加状态，周期、App、用户和兼容看板可从小表精确再聚合，不用对多个看板重复全表扫描。
- 小时分片与聚合子任务记录实现版本和来源版本；代码升级后自动失效不兼容断点，失败后仍可从最后成功小时继续。
- 网络拓扑、Server IP 等粒度不兼容的专项任务保持独立，避免错误混入用户-App核心。

## 4.1 1.0.66 数据库事实心跳

- DWS/ADS 长步骤每 15 秒主动核验 MySQL `PROCESSLIST`、聚合任务锁、当前子任务及小时分片 checkpoint。
- 查到活动语句时明确展示 SQL 已确认存活、连接号、执行秒数、MySQL 状态和 SQL 摘要。
- 数据库可连接但连续 3 次未发现本批次活动 SQL 时升级为 warning 并提示疑似停滞；探测失败会明确报错，不再把应用日志写入能力当作 SQL 存活证据。

## 4.2 1.0.65 执行日志边界修复

## 4.2 1.0.64 RAW 重建稳定性与性能修复

- IPv4 转换统一先使用 `IS_IPV4()` 校验，非 IP 账号不再触发 MySQL 1411，仍可回退到有效 Local IP。
- RAW → CLEAN 按 RAW 主键每 50 万行分块提交；每块单独记录 SQL、连接号、影响行数与耗时，降低单个千万行事务的资源峰值。
- 专属批次 CLEAN 表使用 `TRUNCATE` 快速重建；批量写入期间暂卸二级索引，完成或失败后统一恢复，避免逐行索引维护放大写入成本。
- 完整质量检查移动到 CLEAN 之后并复用已解析字段，不再对千万行 RAW 重复执行日期正则解析。
- DWS/ADS 小时分片及其断点恢复保持不变；真实 Windows/MySQL 1320 万行耗时仍需以目标机器实测为准。

## 4.2 1.0.58 调查页面崩溃保护

- 调查、小时证据、用户证据、Server IP 和已保存调查统一使用 NULL 安全的 MySQL 行解码，兼容旧批次中的可空字段，不再让 `mysql_common` 转换 panic 退出 EXE。
- Finding、数据覆盖、数字和状态显示增加运行时兼容处理；单个异常返回值不会破坏整个调查页面。

## 4.3 1.0.56 聚合崩溃保护与断点恢复

- 将曾导致 MySQL InnoDB semaphore hang 的 hourly V2 整批巨型事务改为按日期与小时切片，每个切片独立事务、独立提交。
- 首次执行为 TCP/Game DWD 物理表建立 `(import_batch_id, stat_date, hour_of_day)` 分片索引，避免每个小时重复全表扫描。
- 新增聚合分片 checkpoint：记录连接 ID、尝试次数、开始/结束时间、耗时、影响行数和错误；重启后跳过已经成功的小时。
- MySQL 命名锁阻止两个 DWS/ADS 聚合同时运行；未完成运行在 MySQL 重启后会标记为 `interrupted`，不再把半成品暴露为可分析结果。
- rebuild、resume 和完整流水线统一输出逐 SQL 与分片日志；心跳文案明确只代表应用线程可写日志，不再误报数据库 SQL 存活。

## 4.4 1.0.55 数据作业中心交互重构

- 数据导入页拆分为“新建导入、批次库、运行任务”三个独立工作区，普通操作者不再面对整条 ETL 的全部技术按钮。
- 批次库使用可搜索状态表展示 RAW、Pipeline、导入行数和可分析状态；选择批次只设置上下文，不再隐式查询流水线。
- 新建、RAW 重建和 DWS/ADS 续跑启动后自动进入任务监控；关闭后恢复必须显式点击加载，保持零数据库访问启动边界。
- 失败、运行中、可分析和仅 RAW 批次分别提供下一步建议；重复的高级操作收敛到开发者诊断模式。
- 真实操作者旅程、前后评分与本机验收步骤见 `docs/design/import-job-center-operator-journey.md`。

## 4.5 1.0.54 修复重点

- 修复刷新批次后自动加载 analysis run 时，历史批次表注册信息中的 `NULL` 再次触发 Rust/MySQL 强类型解码 panic 的问题。
- 批次刷新、选择批次、IP 规则列表和历史流水线恢复全部改为显式操作；页面挂载和刷新批次不再串联隐藏数据库查询。
- Windows `runtime.log` 增加 `import_list_batches` 与 `analysis_list_runs` 的开始/成功标记；若后续仍出现 panic，可直接确定最后执行的命令。
- 修复刷新批次时旧批次元数据包含 `NULL` 导致 Rust/MySQL 强类型解码 panic、Windows 进程直接退出的问题。
- 批次列表查询与 Rust 行解码均增加空值兼容；缺失的数据类型、源文件名和状态会显示为明确的兼容占位值，不再把整个应用带崩。
- 保留 1.0.52 的零数据库访问安全启动、RAW 重建与 SQL 逐语句日志能力。

## 5. 1.0.52 修复重点

- 应用采用零数据库访问安全启动：打开和恢复本地上下文时不再自动加载批次或 analysis run，必须由用户点击刷新。

## 6. 1.0.51 修复重点

## 12. 1.0.44 收口重点

- 进入“系统诊断”不再自动访问 MySQL，必须由用户明确启动诊断任务。
- Catalog、映射、质量、ETL、模块和 Registry 六项检查改为串行任务，展示当前步骤、进度、单项失败和停止后续检查入口。
- 模块深度检查只刷新一次批次表计数，随后 Registry 读取缓存快照，避免一次诊断重复扫描大表。
- Quality / ETL 高级排错和完整执行日志改为展开后才挂载，减少切页时的组件和 DOM 开销。

## 13. 1.0.43 收口重点

- 流水线日志轮询改为单通道执行并按 `sequence` 去重，不再因重叠请求重复显示同一条日志；任务结束时补拉最终日志。
- RAW 质量检查、CLEAN/DWD、DWS/ADS 等长步骤每 15 秒写入存活心跳、步骤耗时和阶段说明，避免大 SQL 执行期间静默。
- 日志区升级为任务监控台，支持刷新健康、静默时长、步骤与级别筛选、搜索、暂停/恢复、手动刷新、排序和复制筛选结果。
- 前台有序保存最多 5,000 条唯一日志，单次渲染限制 600 条；后端并发写日志遇到 sequence 冲突时自动重试。
- 状态与日志只读轮询不再每秒重复执行流水线 schema DDL，降低 MySQL 元数据锁和连接负担；离开导入页后仍可恢复最近一次任务监控。
- 新产生的流水线时间统一以 UTC 写入数据库，流水线监控与执行日志按浏览器所在本地 PC 时区显示，并在界面和复制结果中标明时区。

## 14. 1.0.42 收口重点

- 应用启动、恢复历史批次、选择批次和切换分析页时不再自动执行批次表准备、全表计数或看板查询。
- 每个分析页由用户点击后按需加载；总览任务逐项执行并显示数据集计划、进度、当前步骤、失败结果和停止后续加载入口。
- 高级分析与诊断只在用户展开后挂载，ECharts 只在图表真正显示时动态加载，降低首屏计算与脚本开销。

## 15. 1.0.41 收口重点

- RAW 入库长步骤每 5 秒记录客户端已处理字节、源文件大小和完成百分比，不再在大文件导入期间表现为无响应。
- 文件传输达到 100% 后明确标记“等待 MySQL 解析、索引更新与提交”；连续 30 秒无字节变化时给出分阶段诊断提示。
- 新批次创建后立即绑定到流水线，因此导入未完成时也能看到批次 ID，并支持 `LOAD DATA` 与 Streaming INSERT 两种模式的字节进度。

## 16. 1.0.40 收口重点

- 修复 Rust MySQL 客户端未注册 `LOCAL INFILE` 数据处理器、导致 MySQL 接收到空文件并返回 0 行且无 warning 的问题。
- `LOAD DATA LOCAL INFILE` 现在以 1 MiB 缓冲流式传输用户当前选择的 CSV，不会把 1 GB+ 文件整体载入应用内存。
- MySQL 发起的本地文件请求必须解析为当前选择文件的同一规范路径；其他路径会被拒绝，处理器在单次导入后立即移除。

## 17. 1.0.39 收口重点

- RAW 导入不再接受“0 行成功”：LOAD DATA 与 Streaming INSERT 均验证批次物理表可见数据，0 行时在 RAW 步骤直接失败并返回分隔符、文件和 MySQL warning 证据。
- CSV Probe、字段映射、LOAD DATA 和 Streaming INSERT 统一使用有界探测得到的逗号、Tab 或分号分隔符。
- 数据画像改为查询批次物理 RAW 表；流水线失败后自动展示 RAW 状态和 Quality Gate 失败项。
- 补齐客户 TCP 样例中的平均带宽和用户有效下载速率字段别名。
