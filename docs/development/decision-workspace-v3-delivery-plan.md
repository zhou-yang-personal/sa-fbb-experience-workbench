# Decision Workspace V3｜开发节奏与验收计划

更新时间：2026-08-28  
目标版本：1.0.60

## 1. 交付原则

1. 数据正确性优先于图表数量；0、NULL、未导入、不可用、样本不足分别表达。
2. 主分析顺序固定为：整体全景 → 单 App / 用户分布 → 质差证据 → Cable/FTTH 专项 → 潜客机会。
3. 看板查询只读 DWS/ADS，不扫描 RAW；大型聚合在数据中心显式执行。
4. 每个分析运行绑定不可变规则快照；同一运行恢复时复用已成功子任务。
5. 旧 V2 表和接口保留，避免破坏既有批次；V3 以加法迁移落地。

## 2. 开发节奏

### 阶段 A：需求和口径冻结（已完成）

- 全量需求已写入 `docs/requirements/current-requirements.md`。
- 冻结唯一 App 口径、IP 用户口径、Others 显式配置、四类潜客、问题侧证据措辞和五入口主导航。

### 阶段 B：规则、聚合与恢复（已完成代码）

- migration 011 新增决策规则、运行绑定、潜客结果和子任务 checkpoint。
- 全景、App、用户、质差证据和接入对比复用 V2 用户×App DWS。
- 迁转、升套、AP/组网、App Bundle 独立物化；AP 缺少 Wi-Fi 聚合时返回不可用。
- DWS/ADS 每个子任务独立记录开始、完成、失败、耗时和尝试次数；恢复时跳过 success。

### 阶段 C：傻瓜式交互（已完成代码）

- 一级入口收敛为全景洞察、质差分析、Cable/FTTH、潜客机会和数据中心。
- 批次选择、分析运行和加载动作分离；页面切换不自动查询。
- 技术 ID、数据库、路径、导出目录收进技术上下文；规则与诊断降为二级入口。

### 阶段 D：业务页面（已完成代码）

- 指标视角：用户、流量、观测、持续/严重质差、有效下载速率、时延、丢包；上行速率缺字段时明确不可用。
- App 视角：唯一 App 总表、互斥状态高亮、总量优先、单 App 用户分布下钻。
- 用户视角：流量、时长、观测、速率、用户/网络 RTT、用户/网络丢包和持续质差分档。
- Cable/FTTH：独立页面比较用户、流量、有效速率、时延、丢包和质差比例。
- 潜客：四种类型、候选数、高优先级数、规则版本和数据限制。
- 一次读取全部非空业务图表并通过系统打印对话框导出 PDF；默认不输出明细表。

## 3. 必须明确的数据限制

- 当前 TCP DWD 没有可靠的上行速率字段；不能用 RTT、峰值或下行速率代替。
- 当前 TCP 使用时长尚未进入 V2 DWS，时长分档仅能明确标记为 Game-only / partial。
- AP/组网需要 Wi-Fi delay 进入用户级聚合；未进入前不生成候选。
- Game 文件未导入时显示 Not imported / Unavailable，不显示 0。
- 当前批次只有 1 个有效 BRAS、0 OLT、0 PON，网络设备定位不进入主链路。
- CRM、FTTH 覆盖、套餐、欠费、黑名单和可触达数据缺失时，机会不是“可直接营销名单”。

## 4. 验收门槛

- 前端：`npm run check`、`npm run build`。
- Rust：`cargo check`、全部单元测试。
- SQL：MySQL 8.0 migration 011 实际执行；目标 batch 聚合与查询 smoke。
- 性能：看板不扫描 RAW/DWD；同一 MySQL 只允许一个聚合；恢复不重复成功子任务。
- 语义：所有 rate 可追溯分子、分母、样本和规则版本；不可用不转成 0。
