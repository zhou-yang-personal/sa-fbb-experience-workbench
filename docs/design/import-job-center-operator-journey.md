# 数据作业中心｜真实操作者旅程与体验评分

## 1. 评估方法

本评估按桌面端真实操作者完成任务的顺序走查，不按 React 组件或 ETL 表结构评估。每个场景从五个维度评分：入口可发现性、下一步明确度、状态反馈、误操作防护、完成闭环；每项 2 分，总分 10 分。

评估边界：本轮通过代码路径和界面状态走查验证交互，不连接客户 MySQL，不启动或打断正在运行的 RAW 重建任务。真实 Windows/WebView2 与 1320 万行批次仍需本机验收。

## 3. 改造后的操作者路径

### 场景 A：第一次导入 TCP CSV

1. 进入“数据导入与批次”。
2. 默认停留在“新建导入”，页面只展示一个主任务。
3. 选择 CSV，确认自动生成的可读批次名称。
4. 刷新已发布 IP 规则，选择规则版本并确认 Others 映射。
5. 点击“启动导入分析计划”。
6. 系统进入“运行任务”，展示阶段、百分比、耗时和日志。

### 场景 B：第二天继续观察长任务

1. 打开应用，不自动访问数据库。
2. 进入“运行任务”，看到本机保存的任务 ID 和“尚未加载”状态。
3. 点击“加载最近任务状态”，此时才读取 MySQL 状态与增量日志。
4. 操作者可开启或暂停自动刷新，不会启动第二个处理任务。

### 场景 C：规则变化后复用 RAW

1. 进入“批次库”，手动刷新批次列表。
2. 搜索批次名或 ID，点击“选择批次”；选择动作本身不查询任务详情。
3. 查看 RAW、Pipeline、行数和 analysis run 摘要。
4. 点击“加载任务状态与日志”确认没有活跃任务。
5. 返回批次库，点击“从 RAW 重建 CLEAN / DWS / ADS / V2”。
6. 二次确认后进入任务监控。

### 场景 D：聚合失败后恢复

1. 在“运行任务”查看失败步骤和 SQL 日志。
2. 点击“去批次库选择恢复方式”。
3. CLEAN 已成功且只缺 DWS/ADS：选择“复用当前批次继续生成完整看板”。
4. CLEAN 未完成、规则或清洗口径已变化：选择“从 RAW 重建”。
5. 若历史状态仍为 running，只有确认原 EXE 已退出后才能申请接管，后端继续检查活动 SQL。

## 4. 已修复的问题

- 将一个超长页面拆成“新建导入 / 批次库 / 运行任务”三个互斥工作区。
- 批次由长下拉框改为可搜索状态表，直接显示 RAW、Pipeline、行数和业务就绪状态。
- 选择批次不再隐式加载流水线；任务恢复、日志加载和自动刷新均为显式操作。
- 新建、重建或续跑成功启动后自动进入任务监控，避免操作者寻找日志。
- 根据批次状态提供下一步建议，并为失败任务提供返回恢复入口。
- 合并重复的高级操作入口；手工步骤和诊断输出仅在“运行任务”的开发者诊断区展开。
- 保留运行中批次删除保护、接管确认和后端活动 SQL 校验。

## 5. 本机验收清单

- 打开应用后，在点击任何按钮前确认 MySQL PROCESSLIST 没有新增应用查询。
- 新建导入启动后确认自动切换到“运行任务”，日志只出现一份且 sequence 不重复。
- 重启应用后确认不会自动加载任务；点击“加载最近任务状态”后才出现状态和日志。
- 在批次库选择两个不同批次，确认不会自动查询或混用上一批次日志。
- 对 success、failed、running、仅 RAW 四种批次分别核对建议动作和按钮状态。
- 验证运行中批次无法删除，删除确认明确列出影响范围。
- 在 Windows 100% 和 125% 缩放下检查批次表、按钮和日志不截断。
